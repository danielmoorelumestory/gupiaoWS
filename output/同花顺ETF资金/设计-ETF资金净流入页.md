## 1. 意图与为什么

做一个**部署在服务器上、每天收盘后自动更新**的网页，用来看 **ETF 资金净流入的大周期趋势**——一段时间里资金整体在流入还是流出，作为市场情绪/择时的参考输入。

对标截图中间那块「历史ETF申购净流入」：红绿日柱 + 上证指数叠加 + 时间轴拖动。只做 **全A** 和 **宽基** 两条口径。

同花顺原口径（`etf_net_buy_flow_amount` 等）和盘中预估曲线匿名拿不到，因此全程用公开数据**自建估算**，不声称与同花顺逐位一致。

## 2. 目标 / 非目标 / 反目标

**目标**
- 展示全A、宽基两个口径的**日度净流入**（红绿柱）+ **上证指数**叠加 + 可拖动时间轴。
- 顶部 KPI：昨日净流入、近 60 日累计净流入（全A / 宽基各一组）。
- 每日收盘后数据到齐时自动更新一次。
- 静态页部署，运维极简。

**非目标**（本期不做）
- 顶部**盘中实时预估曲线**——匿名不可得，彻底不做。
- 底部**单只 ETF 资金榜 / 指数资金榜**——选股工具，与大周期无关。
- 行业 / 黄金 / 港股**分类**——只做全A + 宽基。
- 与同花顺**逐位对齐**、快讯校准——不求精细，接受 ~1% 日误差与少量累计漂移。

**反目标**（即使"能跑"也算失败）
- 为追求盘中实时而上一版自编的瞎估曲线，误导为真实数据。
- 把份额**折算/拆分**日的假跳变画成巨量净流入，污染大周期判断。
- 把估算值包装成"同花顺原值"。

## 3. 约束

- 只用**匿名、不登录**的公开接口（已实测通）。
- 价格口径固定用 **NAV**（东财 lsjz）；不求精细，不用成交均价。
- 数据是 **T+1 日频**：净值当晚约 19:00–21:00 到齐，QDII/港股更晚。更新时点取当晚净值到齐后或次日早上。
- 需一台常开服务器跑定时任务 + 托管静态页。

## 4. 方案选型（已决策）

**架构：A — 静态页 + 定时重算**（已选）
- cron 每晚跑 Python 采数、算净流入 → 写 `data.json` → 静态 HTML + ECharts 读它。
- 备选 B（Flask/FastAPI 常驻后端实时查库）被否：一天一更、看大周期，静态完全够，B 多一个常驻进程、徒增运维与故障面，是过度设计。

**价格口径：NAV**（已选）
- 备选"成交均价"虽更贴同花顺（单点样本 512400 几乎贴公布值），但要逐只拉日 K、复杂度高，与"不求精细"不匹配，否。

**分类粒度：全A + 宽基两条**（已选）
- 备选"只全A"信息太少；"五分类全保"要维护分类映射且边界同花顺不公开、维护成本高，否。

## 5. 已决定的做法

### 5.1 数据来源
| 数据 | 接口（匿名，已实测通） | 说明 |
|---|---|---|
| 沪市份额 | `GET query.sse.com.cn/commonQuery.do`，`sqlId=COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L` | `TOT_VOL` 单位万份，×10000 为份 |
| 深市份额 | `fund.szse.cn/api/report/ShowReport`（当日）；历史回补用 AKShare `fund_scale_daily_szse`（约 6 个月） | 单位需在实现时核对 |
| NAV | 东财 `api.fund.eastmoney.com/f10/lsjz?fundCode=&...` | 取 `DWJZ` 单位净值 |
| 上证指数日K | 东财/新浪指数接口 | 叠加线 |

### 5.2 计算口径
- 单只日净流入 `flow_t = (share_t − share_{t−1}) × NAV_t`，单位元，展示换算为**亿元**。
- **全A** = 当日所有在列 ETF 的 `flow_t` 求和。
- **宽基** = 宽基白名单子集求和。
- 近 N 日累计 = 近 N 个**交易日** `flow` 之和（KPI 用 N=60；"昨日"= 最近一个交易日）。
- 柱颜色沿 A 股惯例：**红=净流入(正)、绿=净流出(负)**。

### 5.3 宽基白名单
- 维护一张 `code → 是否宽基` 的种子 JSON，人工维护。
- 种子池（宽基指数 ETF，实现时补全代码与新发）：上证50、沪深300、中证500、中证1000、中证A500、中证A50、创业板、科创50、科创100、上证180、深证100、双创50、北证50 等及其跨市场份额。
- 分类是**近似**，页面注明。

### 5.4 异常处理（务实档，不求精细但必须防污染）
- **折算/拆分**：单日份额变动绝对值超阈值（实现时定，如 >50%）视为疑似折算 → 该只当日 `flow` 剔除/标记，不计入合计。
- **NAV 缺失/晚披露**：用最近可得 NAV 或跳过当日该只。
- **新上市/退市**：无前一交易日份额 → 跳过（不按建仓算）。
- **交易日历对齐**：按交易日序列取"前一交易日"，非自然日。

### 5.5 存储与产物
- SQLite 累积历史（每日每只的 share、NAV、flow）。
- 导出前端用的汇总 `data.json`：按日的全A/宽基 flow、累计、上证指数序列。
- 页面只读 `data.json`，不直连任何接口。

### 5.6 前端
- 沿用仓库现有 HTML + ECharts 风格（参考 `output/同花顺ETF波段顶底/research/*/page_template.html`）。
- 两 tab（全A / 宽基）；主图：净流入红绿柱 + 上证指数线（双 Y 轴）+ `dataZoom` 拖动；顶部 KPI 卡（昨日、近60日累计）。
- 顶部醒目注明："自建估算（份额差×NAV），非同花顺原口径；无盘中数据，T+1 更新。"

### 5.7 定时与部署
- Python 采数脚本，crontab 每日收盘后（如 22:30）跑一次：采数 → 更新 SQLite → 导出 `data.json`，带日志与失败重试。
- nginx 静态托管页面目录 + `data.json`。

### 5.8 代码落位
- `output/同花顺ETF资金/app/`：采数脚本、SQLite、宽基名单、`data.json`、`index.html`。实现时定细结构。

## 6. 留给实现者（builder）的开放项
- 深交所份额接口的**单位**与历史回补字段核对。
- 份额折算判定**阈值**、ETF 全集（含退市过滤）取法。
- 宽基白名单**最终补全**（代码 + 新发 ETF）。
- 上证指数接口选型、ECharts 具体样式与交互细节。
- SQLite schema、`data.json` 字段结构、cron 具体时点、日志/重试策略、nginx 配置。

## 7. 验收标准
- 页面能切全A/宽基，显示红绿日柱 + 上证指数 + 可拖动时间轴，KPI 正确。
- 跑一次采数后 `data.json` 刷新、页面随之更新。
- 份额折算日不出现异常巨柱。
- 页面明确标注估算口径与局限。
- 用近期某日对同花顺快讯"昨日全市场合计"做一次**抽查**（非持续校准），全A 量级一致（容忍 ~百分之几误差）。
