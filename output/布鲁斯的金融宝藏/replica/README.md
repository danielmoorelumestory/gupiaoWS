# bruce_replica

抖音博主「布鲁斯的金融宝藏」（Bruce_Gold）交易体系里**能复刻的部分**的代码实现。依据是三个合集 51 条视频的逐字稿，以及其中 18 条的画面抽帧核对。体系全貌见上级目录的 `05-交易体系总结与复刻方案.md`，逐项出处见 `03-codex-第二轮.md`。

这不是完整复刻，也不产生买卖信号。它做三件事：算出他公开讲过的指标、把读数对照他讲过的案例、提供他那张交易记录表的模板。

## 安装与运行

```sh
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -m pytest -q          # 37 个测试，用他视频里报过的数字验算公式
```

每个交易日收盘后运行一次：

```sh
.venv/bin/python -m bruce_replica today             # 红盘率、阿姆士、换手率>5%占比，入库并对照案例
.venv/bin/python -m bruce_replica today --stage 中后段 --exclude-st
.venv/bin/python -m bruce_replica pcr --trend 下行   # 期权 PCR 通道：中金所 HO(50)、IO(300)，及他的 50/300 确认规则
.venv/bin/python -m bruce_replica backfill          # 首次使用：回补历史涨跌家数，让 MCL 可用（耗时长，可续跑）
.venv/bin/python -m bruce_replica spread            # 股债利差通道：当前位置、历史触轨时段、他点名时点的对照
.venv/bin/python -m bruce_replica valuation         # 估值旁证：总市值/GDP、市盈率与市净率的历史位置、三只宽基 ETF 成交额
.venv/bin/python -m bruce_replica backtest          # 把他明说的规则写死做历史回测（需先回补好数据）
.venv/bin/python -m bruce_replica tech              # 上证指数周线、日线的技术面读数
.venv/bin/python -m bruce_replica combine 空 多      # 资金面与技术面合成结论
.venv/bin/python -m bruce_replica journal           # 新建空的交易记录表
```

`today` 取全市场截面约需 4 分钟。截面和每日汇总存在 `data/`（不进 git）。

## 实现了什么

| 模块 | 内容 | 参数来源 |
|---|---|---|
| `breadth.py` | 红盘率；阿姆士（成交额、成交量两种口径）；麦克莱伦摆动 MCL；均线上方个股占比 P20/P60/P250 | 阿姆士公式：第21集 00:48 画面。MCL 19/39：第22集 04:40 画面代码。P 的定义是推断 |
| `technical.py` | 一目均衡表 7/22/44、VWMACD 12/26/9、布林带 20、CCI 14、唐奇安通道、KDJ、日线合成周线 | 前四项来自第19集画面；布林带倍数 2、唐奇安 20、KDJ 9/3/3 是自选默认值 |
| `pcr.py` | 期权 PCR 标准差通道：击穿上轨为顶、下轨为底；50 与 300 的确认规则；单边行情首个反向信号降级；无信号空仓 | 规则：金融宝藏第3集、第7集口述。20 日、2 倍来自第3集画面的 `BB 20 2`；中金所持仓量口径由第7集画面数值核对确认 |
| `midterm.py` | 股债息差与标准差通道及判读（上轨为底、下轨为顶）、总市值/GDP 区间、估值历史分位、三只宽基 ETF 成交额合计与 20 日均线、换手率>5%个股占比 | 总市值/GDP 的 1.00/0.70/0.50 来自第11集画面；通道窗口和倍数是自选默认值 |
| `rules.py` | 资金面与技术面的合成规则；阿姆士参考档；当天读数与他 10 个案例的比对；缩量普涨判定（红盘率≥80% 且阿姆士>1） | 合成规则：第26集 02:10–03:23。参考档 0.7/0.6/0.5：第21集 01:24。案例见代码里的出处 |
| `backtest.py` | 事件合并、信号后涨跌与基准对比、进出场状态策略 | 方法是研究者设定 |
| `journal.py` | 交易记录表模板（基本面 5 栏、技术面 5 栏、结论、仓单 13 栏、账户 2 栏） | 第26集 01:20–03:58 画面逐栏还原 |
| `data.py` | AKShare 取数、截面存档、每日汇总 | 数据源是我们选的，与他用什么无关 |

代码里凡是写「研究者自选」的参数，都不是他给的。

## 回测结论

十一条规则里明确有效的两条：息差触上轨是底（20 年 9 次，半年后 7 次上涨，平均 +13%，平时 +4.7%）；300 的 PCR 破下轨而 50 没破时短期续跌（20 次，一周内 14 次）。息差破下轨当顶不可靠；PCR 击穿上轨开空与抛硬币无异；缩量普涨之后指数反而比平时更容易涨。完整表格和说明见上级目录终稿第 6 节。回测需要的长历史数据（中金所期权 2019-12 起、个股日线 2015 起）要单独下载，见 `data.py` 里的 `backfill_cffex_options` 和 `backfill_stock_hist(subdir="hist_long")`。

## 使用时要知道的限制

- **MCL 靠回补的历史数据。** `backfill` 命令逐只下载全市场个股日线（约六千只，一到两小时，可续跑），汇总出每天的涨跌家数和阿姆士。已回补 2025-06-03 起 351 个交易日。股票池是下载时仍在上市的股票，期间退市的不在内。之后每天跑 `today` 即可续上。
- **他报的读数大多能重现。** 用回补数据核对他讲过的 10 个读数：红盘率 9 个差在 1.5 个百分点以内（11/09 他说约 45%，算出 40%）；阿姆士按成交额口径，7 个吻合（9/22、9/23、3/23、7/21、10/27、11/05、11/09），9/21（他 1.69，算出 1.92）、10/23（0.90 对 1.12）、10/28（0.77 对 0.90）偏差较大。11/04 他说 1.6，成交额口径是 1.01、成交量口径是 1.64，那天他用的是量。
- **读数未必和他的一致。** 他没说股票池含不含北交所、ST 和平盘怎么处理、阿姆士用量还是额。这些都做成了开关（`--no-bj`、`--exclude-st`、`--flat-as-down`），两种口径的阿姆士同时输出。
- **案例比对不是信号。** `today` 只告诉你当天读数最像他讲过的哪一天、他当时怎么解读。距离尺度是我们定的。他自己说过不能只看数值大小，要结合位置和阶段。
- **「趋势中后段」需要人工判断。** 他要求阿姆士和宽广度只在趋势中后段使用，但没有给出可计算的定义，所以 `--stage` 由使用者填。
- **股债利差通道与他的说法吻合，但口径是近似。** 用沪深300 股债利差（盈利收益率减 10 年国债）、750 日 2 倍滚动通道：2019 年以来触上轨 5 次（2019-01、2020-03、2022-04、2022-10、2024-09），都在阶段低点附近；破下轨 3 段（2021-01~02、2025-08~10、2026-01）。他点名的 2024/9、2025/4 读数为 +1.95σ、+1.99σ，2020 年底 −1.68σ（次月破下轨），2026/9/16 −0.19σ（他说在中轨）。他说的是全市场口径，窗口和倍数没给；750 和 2 是写代码时先定的默认值，没有为了对上而调。破下轨的状态会持续很久（2025-08 起近一年都贴着下轨，其间指数还涨了一成多），当顶部信号用很钝。
- **估值三项：两项对上，一项只是接近。** 总市值/GDP 现为 0.84，他 10/16 画面右端在 0.8–0.9 之间；2024 年「924」前是 0.57（低于他的 0.70 低估线），2021 年顶部是 0.91（接近 1.00 高估线），和他的说法一致。三只宽基 ETF 成交额合计：他画面末端显示 96.41、20 日均 105.41，我们算出 9/29 正是 96.41 和 105.41。他第14集的估值图标的是沪深300（画面指数 4170.61 即 10/16 收盘），画面 PE 13、机会值 11.61、危险值 14.18；沪深300 静态市盈率近十年 20%/80% 分位是 11.52/14.16，危险值几乎对上，机会值差 0.1，PE 本身是 13.56，算法没有确认。
- **PCR 的口径已对上，信号日期只部分吻合。** 他图上的 300、50 PCR 是中金所股指期权 IO、HO 的持仓量认沽/认购比：9/30 画面值 0.7491、0.7329，用中金所日统计算出来四位小数全对；50 的 20 日 2 倍通道三条轨也对到 0.001 以内，300 的轨差约 0.01（原因未查明）。9/28–29 IO 破下轨而 HO 没破，重现了他 9/30 讲的情形。他回顾时口述的 13 个历史日期里，前后一两天内触轨且方向一致的有 5–6 个，其余多数方向一致但只到 1.2–1.7 倍，3 个对不上。左图的「全市场加权」算法仍然没有；`--source sse` 可看上交所 ETF 期权，但那个口径对不上他的数值。
- **技术面只给读数。** 顶背离、出云失败这类形态他是看图判断的，代码不识别。
- **`tech` 周线的日期是所在周的周五**，周内运行时最后一根周线尚未走完。

## 同花顺 ETF 主升浪（每日采集）

`uptrend.py` 每天采集同花顺「ETF 主升浪」榜单（全量名单、趋势回踩、新入池），按日保存快照，按标的缓存历史上涨区间与同花顺 AI 上涨原因，并生成页面 `../charts/ths-etf-uptrend.html`。只用标准库，系统 `python3` 即可运行。接口与验证经过见 `output/同花顺ETF主升浪/README.md`。

```sh
python3 -m bruce_replica uptrend run                    # 手动采集/补跑；当天已有快照则安全覆盖，失败不覆盖
python3 -m bruce_replica uptrend show [--date 2026-11-13]
python3 -m bruce_replica uptrend page                   # 只重新生成页面
python3 -m bruce_replica uptrend schedule install [--time 20:30]   # 注册/更新 launchd 每日任务（北京时间）
python3 -m bruce_replica uptrend schedule status        # 是否已加载、本机触发时间、下次触发、最近运行
python3 -m bruce_replica uptrend schedule uninstall     # 停用
python3 -m unittest tests.test_uptrend                  # 关键逻辑测试
```

- 定时：launchd 任务 `com.gupiaows.ths-etf-uptrend`，默认北京时间 20:30，按本机时区换算写入 plist；本机时区变化后 `status` 会提示重新 install。Mac 睡眠错过的会在唤醒后补跑。`run --scheduled` 当天已有定时点之后（或来源截止日已是当天）的成功快照就跳过；文件锁防止并发重入。
- 存储 `data/ths_uptrend/`：`snapshots/日期.json`（规范化名单）、`latest.json`（最近成功）、`raw/日期/运行号.json.gz`（本次全部原始响应）、`runs.jsonl` 与 `status.json`（每次运行状态与失败信息）、`cache/periods`、`cache/reasons`、`logs/`、`config.json`（`time`、`period_budget` 120、`reason_budget` 40、`min_interval` 0.35 秒等可改）。
- 名单失败不写快照、不动 `latest.json`；页面显示失败提示和此前最近成功数据。历史区间/原因部分失败记为 `partial`，下次补。
- 「来源截止日」取本次新取到的在池 ETF 当前上涨区间的 `end_day`；早于采集日时快照里会写明，不当作当日行情。
- 没有今日涨幅、盘中累计涨幅、连续上涨天数、涨停指标（需登录，401）。名单为接口原序，不是排行。历史快照只从 2026-11-13 起积累。

## 没有实现的部分

- 中期层的数据抓取：汇金与中证金融持仓、高管增减持比例；股指期货升贴水和主力合约流入流出。计算函数有，自动取数没写。
- 他没有公开或口径不明的：CFTC 持仓的二次加工算法、「资本2」「筹码」「债券仓位占比」「额价差」、恒生「定价权系统 C」、综合评分和形态回测脚本；境内美元拆放利率、离岸主权债等他只提了名字的观察点。
- 期权的合约选择、滚动和仓位规则：他只给了案例，没有成套参数。
